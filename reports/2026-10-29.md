## 1 Chrome: Gmail에서 가져오는 자동완성 제안

### 공식 근거·달라진 점

[Google 공식 발표](https://blog.google/products-and-platforms/products/chrome/enhanced-autofill-gmail/)는 2026-10-28부터 Gmail의 주문번호·배송 정보·항공편 예약 같은 내용을 양식 입력 중 제안한다고 설명합니다. Gemini의 Personal Intelligence를 사용하는 enhanced autofill 확장입니다. 기존 이름·주소·카드 자동완성이나 앞서 본 메뉴 개편을 새 기능으로 재포장한 것이 아닙니다.

### 범위와 제약

미국의 desktop·Android·iOS에서 Gemini in Chrome을 이용하고 Personal Intelligence를 활성화한 사용자에게 배포를 시작합니다. 구체적인 Chrome 최소 버전, 계정 티어·언어·연령, 관리 계정 지원과 한국 제공 일정은 이 발표에 없습니다. 미국 전체 사용자의 즉시 활성화를 뜻하지 않습니다. 설정에서 활성 여부와 접근 범위를 관리할 수 있고 민감한 데이터는 암호화한다고 설명하지만, 세부 처리 위치·보존 기간을 본문만으로 확정하지 않습니다. 자동 제출·예약 실행 기능으로 해석하지 않습니다.

### 사용자 영향·제품 비교

메일 검색과 복사·붙여넣기를 줄일 가능성이 있습니다. 반면 비슷한 주문 여러 개, 오래된 예약, 취소된 항공편이 섞이면 잘못된 값을 고를 위험이 있습니다. 제품 비교는 제안의 출처·시점 표시, 삽입 전 확인, 접근 해제와 잘못된 정보 수정의 쉬움에 초점을 둡니다. 삼성 브라우저가 같은 데이터 연결을 제공하는지는 별도 확인 질문입니다.

### 벤치마크 후보 — P1, 미실행

- 과제: 합성 주문·항공편 메일에서 정확한 예약번호를 찾아 공개 시험 양식에 입력하되 제출하지 않기.
- 비교군: 동일 Windows PC의 기능 노출 Chrome과 수동 Gmail 검색·복사. Android는 동일 단말에서 별도 실험하며 desktop과 평균을 섞지 않습니다. Firefox 158/159의 열린 탭 기반 제안은 데이터 원천이 다르므로 별도 조건으로만 비교합니다.
- 재현: 승인된 시험 계정·합성 메일만 준비 → 빌드/지역/계정/설정과 기능 노출 기록 → 정상·동일 상점 중복·취소 후 변경 3조건을 각 5회 교차 실행 → 출처 확인·삽입·수정 → 접근 해제 후 제안 여부 확인.
- 측정: 완료 시간, 탭 전환/조작 수, 정확한 값 비율, 오래된 값 제안, 출처를 이해하는 비율, 해제 후 잔류 제안.
- 완료 기준: 15회 결과와 제안/수정/해제 화면 증거를 확보하고 미지원 조건을 별도 표시합니다. 실제 사내 메일·개인 예약·결제 정보는 사용하지 않습니다. 연결 권한 변경과 데이터 준비는 별도 승인된 시험에서만 수행합니다.

## 2 Firefox 160 Beta: Mini Window의 초기 시험 범위

### 공식 근거·날짜

[160 Beta 공식 노트](https://www.firefox.com/en-US/firefox/160.0beta/releasenotes/)는 탭 또는 페이지 일부를 항상 위에 있는 작은 창으로 띄우는 Mini Window를 초기 기능으로 명시합니다. [10월 27일 로드맵](https://blog.mozilla.org/en/firefox/firefox-roadmap/)에서 개발 예고로만 다뤘던 내용을 Beta 채널의 구체적인 시험 후보로 보완합니다. 전날 보고의 Stable 미확인 판단은 유지합니다.

### 영향·비교 포인트

레시피·작업 지침을 보면서 다른 탭을 조작하는 과제에서 창 전환 부담을 줄일 가능성이 있습니다. 영상만 분리하는 PiP와 페이지 일부를 유지하는 기능은 다른 과제입니다. 작은 창의 클릭·스크롤·키보드 포커스와 원본 탭 복귀, 민감한 영역이 계속 노출되는지 확인해야 합니다. 삼성·Chrome·Edge의 대응은 실제 기능 확인 후 비교합니다.

### 벤치마크 후보 — P2, 미실행

- 동일 Windows PC·화면 배율·해상도·합성 지침 페이지에서 Firefox 160 Beta Mini Window와 일반 창 2개 수동 배치를 비교합니다.
- 재현: 5단계 지침을 보며 별도 탭의 합성 체크리스트 작성 → 전체 탭/선택 부분 조건 분리 → 창 크기 변경·다른 앱 전환 → 원본 탭 탐색/닫기 후 분리 창 상태 확인. 각 5회.
- 지표: 작업 시간, 창 전환 수, 잘린 지침·오입력, 포커스 분실, 닫기/복귀 조작 수.
- 완료 기준: 양 조건 각 5회와 원본 종료/탐색 시 동작 증거를 확보합니다. 기능이 보이지 않으면 미지원/미노출로 기록하고 강제 플래그 변경으로 정상 배포처럼 만들지 않습니다.
- 제약: Beta의 초기 기능입니다. OS별 차이, 진입 메뉴, 영역 선택 제약, 지역·계정 제한, 정식 포함 여부는 미확인입니다. 공개 자료에 없는 제한을 ‘없음’으로 쓰지 않습니다.

## 3 Firefox 160 Beta: PiP 창 안의 재생 속도 설정

### 공식 근거·범위

[160 Beta 공식 노트](https://www.firefox.com/en-US/firefox/160.0beta/releasenotes/)는 PiP에 0.25배–2배 속도 설정을 추가하며 중간 이상 크기의 창에서만 표시한다고 설명합니다. [기존 PiP 도움말](https://support.mozilla.org/en-US/kb/about-picture-picture-firefox)은 영상 분리와 크기 조절의 기존 흐름을 설명합니다. PiP 자체의 신규 출시가 아닙니다.

### 영향·비교 포인트

강의 속도를 바꾸려고 원래 탭으로 돌아가는 부담을 줄일 수 있습니다. 작은 창에서 옵션이 사라지는 조건은 발견 가능성과 접근성의 비교 포인트입니다. 사이트 플레이어의 속도 설정과 브라우저 PiP 설정이 충돌하는지도 확인 질문입니다.

### 벤치마크 후보 — P2, 미실행

- 같은 Windows PC·공개 합성 영상·자막·창 크기로 Firefox 159와 160 Beta, 실제 속도 제어가 확인된 Chrome/Edge/삼성의 PiP를 비교합니다.
- 재현: 1배로 영상 시작 → PiP 분리 → 1.5배와 0.75배로 바꾸기 → 작은 창/중간 창 전환 → 원본 탭으로 복귀. 각 조건 5회, 동일 구간을 사용합니다.
- 지표: 속도 변경 조작 수·시간, 실제 재생 속도, 자막/음성 동기, 크기 변경 시 값 보존, 키보드 접근.
- 완료 기준: 창 크기별 노출과 복귀 후 값, 5회 결과를 기록합니다. 공식 미공개인 픽셀 임계값은 직접 관찰 전 채우지 않습니다.
- 제약: Beta만 확인했으며 개별 사이트·DRM 영상·Android 지원은 확정하지 않았습니다. Beta 항목이 최종판에 반드시 포함되는 것은 아닙니다.
