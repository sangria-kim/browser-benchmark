## Brave · 사이트 도구용 WebMCP API 기본 활성화 (Nightly 소스)

- Feature ID / Event ID: brave-leo-website-tools / brave-webmcp-default-nightly-11022-20261112
- Brave 1.102.2 Nightly · Windows/macOS/Linux · pc · ai_related=true
- selected / P2 / 준비 상태 conditional. 실제 설치본 시험은 미실행.

### 변경과 근거

WebMCP 도구 자체는 이전부터 실험 중이었다. [공식 PR #40616](https://github.com/brave/brave-core/pull/40616)은 11월 12일 02:52:49 UTC 병합됐고 WebMCP runtime 기본값과 base-feature 연결을 변경했다. 빌드 봇이 연결한 [1.102.2](https://github.com/brave/brave-browser/releases/tag/v1.102.2)는 같은 날 13:23:36 UTC 공개된 **Nightly**다. 소스의 stable 문자열은 Brave Stable 채널 출시가 아니다. 이 변경은 API/runtime 기본값이며 모든 Leo UI의 노출이나 사이트 도구 자동 승인을 증명하지 않는다. 개별 기능의 최초 활성화일은 미확인이다.

### 사용자 영향과 PM 판단

Leo가 페이지를 읽고 클릭하는 대신 사이트가 제공한 도구를 호출한다. [공식 도움말](https://support.brave.com/hc/en-us/articles/50132604817165-How-do-I-use-Website-Tools-in-Brave-Leo)은 이미 로그인한 일반 프로필과 사용자가 연결한 탭을 이용하며, 매번 묻기·현재 세션 허용·차단·사이트 연결 해제를 안내한다. 여러 사이트를 연결하면 대화 내용이 다른 사이트로 전달될 위험이 있다. 제한된 사이트와 모델에서만 가능한 Nightly 변경이므로 P2로 비교한다.

삼성 브라우저의 지원 유무를 전제하지 않고, 사이트 연결·실행 인자·승인 지속 범위·해제를 사용자가 명확히 통제할 수 있는지 질문한다.

### 벤치마크 후보

- 과제: 합성 주문 내역을 검색하고 결과를 바탕으로 메시지 초안을 만든다. 실제 계정·결제·발송은 사용하지 않는다.
- 비교 대상: 동일 Windows 장치의 Brave Nightly 1.102.2 이상과 실험 기능이 수동 활성화되는 이전 빌드. 삼성 브라우저는 대응 공개 기능 확인 후 별도 비교한다.
- 동일 조건: HTTPS 시험 사이트, 동일 합성 데이터·도구 스키마·모델·언어. 새 시험 프로필의 flags 기본값을 기록한다.
- 단계: 도구 탭 연결 → 인자 확인 후 1회 허용 → 같은 도구 재요청 → 세션 허용과 차단 각각 시험 → 사이트 연결 해제 → 새 대화에서 권한 잔존 여부 확인.
- 지표: 작업 성공률, 승인 횟수, 실제 전송 인자, 사이트별 도구 경계, 해제 후 실행 차단, 예상 밖 데이터 전달.
- 완료 기준: 조건별 3회 기록. 거부·해제한 도구가 실행되지 않는지와 새 대화에서 권한이 초기화되는지 확인한다. 기능 미노출과 실패를 구분한다.

### 출시 제한과 한국 지원

도움말은 Desktop, Brave 1.96+, 도구 지원 모델, HTTPS 및 수동 flag 활성화를 요구한다. 최신 Nightly 소스의 기본 활성화와 문서가 맞지 않아 설치본에서 재확인이 필요하다. Android/iOS·Stable 확대·한국 제공·한국어 지원·한국 적용일은 미확인이다. 실험 기능으로 다루며 모든 설치본 사용 가능으로 표현하지 않는다.

- 판정 규칙: pm-selection-v2. 기본값 변경과 승인 경계가 비교 가치이며, 최초 도입·정식 출시로 선정한 것이 아니다.
