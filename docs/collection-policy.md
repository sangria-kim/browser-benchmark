# 브라우저 기능 수집 기준

[출처 설정](../config/sources.yml)에서 활성화한 브라우저별 출처를 조사합니다. 조사 기간은 2026년 1월 1일 한국시간부터 지정한 마감까지입니다. 날짜만 제공된 자료는 원문 날짜를 따릅니다. 날짜를 확인할 수 없는 기능은 적용일을 미확인으로 기록합니다.

## 기능 판정

수집 에이전트는 각 업데이트를 항목 단위로 읽고, 어떤 브라우저에서 사용자가 무엇을 새로 할 수 있는지 또는 기존 동작이 어떻게 달라졌는지 확인합니다. 브라우저가 웹사이트나 관리자에게 제공하는 API·설정의 구체적인 변화도 포함합니다.

- 탭 그룹 공유 추가, 사이트별 권한 제어 변경, 특정 플랫폼 지원 확대, 기존 기능 제거처럼 공식 근거로 확인되는 변화를 저장합니다.
- 취약점 패치, 일반 오류 수정, 내부 코드 정리, 단순 버전 상승, 홍보, 행사, 반복 공지와 파싱 실패는 건너뜁니다.
- 섹션 제목이나 단어만으로 판정하지 않습니다. 보안 관련 새 기능도 구체적인 동작이 확인되면 포함합니다. 하나의 문서에 기능과 수정이 섞여 있으면 기능을 설명하는 항목만 선택합니다.
- 기능은 브라우저와 기존 기능 키로 묶습니다. 버전, 채널, 플랫폼, 공식 URL, 근거 문장과 확인된 날짜를 유지합니다. 예고·실험·베타·정식 출시를 구분합니다. 확인되지 않은 출시나 설치본 동작을 추정하지 않습니다.

공식 출판자 URL에서 구체적인 기능을 확인하면 한 건씩 저장할 수 있습니다. 기존 기능 키나 ID를 사용하며 같은 문서의 서로 다른 기능은 따로 판정합니다. 근거가 있으면 버전·플랫폼·채널·배포 상태를 해당 기능에 연결합니다. 미확인 값은 비워 두고 다음 조사에서 보강합니다. 인용문, 원문 사본, 설치본 확인은 선택입니다. 출처만 추가하거나 빈 값을 채울 때는 제품 변경 건수를 올리지 않습니다. 예정된 조사를 모두 마친 경우에만 전체 0건을 확정합니다.

## Edge 정책 근거

Edge PC·모바일 Stable·Beta 공개 릴리스 노트에서 기능을 찾습니다. 매일 07:00과 일요일 10:00 한국시간 수집에서 정책 목록과 전체 상세를 조회하지 않습니다. 정책 목록에만 나온 항목은 정기 후보에 포함하지 않습니다.

선택한 기능의 적용 조건, 정확한 지원 플랫폼 또는 버전을 확인할 때만 해당 릴리스 항목이 직접 연결한 공식 정책 상세 한 건을 확인합니다. 연결이나 조건을 확인할 수 없으면 미확인으로 둡니다. 기존 정책 근거와 참조는 계속 유효합니다. [Edge 정책 확인 절차](../pipeline/OPERATIONS.md#edge-정책-상세-확인)

## 저장 범위

전체 후보, 원문 캐시와 분류 작업 파일은 저장소 밖에서 다룹니다. 공개 저장 대상은 판정한 기능과 이를 뒷받침하는 출처 항목입니다. 이전 수집 자료의 ID와 경로는 이력 조회를 위해 유지합니다.

비교 우선순위, 평가 점수, 벤치마크 계획, 일일 리포트, 사내 반입 준비는 수집 완료 조건에서 제외합니다. 운영 로그, 인증 정보, 개인 식별자, 사내 분석은 공개 자료에 넣지 않습니다. [실행 안내](../pipeline/OPERATIONS.md)


## Firefox iOS 공식 릴리스 노트

버전별 Mozilla 페이지와 수집 마감 시점의 아카이브를 우선한다.
아카이브에 해당 버전의 기록이 없거나, 버전별 페이지가 404 또는 410을 반환하면
[미국 App Store의 Firefox 버전 기록](https://apps.apple.com/us/app/firefox-fast-private-browser/id989804926)에서 같은 버전을 확인한다.
App Store 본문이 이미 확인한 Mozilla 기록과 다르면 대체하지 않는다.

고정된 앱 ID와 Mozilla 개발자 계정을 확인한다. 같은 버전 기록 행의 버전, 게시 시각,
본문이 구조화된 데이터와 일치해야 한다. 수집 기간은 GitHub 태그가 아닌 App Store
게시 시각으로 판정한다. 확인할 수 없는 버전은 완료 처리하지 않는다. 일반 유지보수
안내를 새 기능으로 집계하지 않는다. 재개는 기존에 내려받은 기록을 재사용한다.
게시 내용이 바뀌었는지 확인하려면 별도의 수집을 시작한다.

App Store 게시 시각과 GitHub Release 게시 시각의 선후 관계로 근거를 거부하지 않는다.
두 출처의 게시 시각은 서로 다른 사건이다. 앱·개발자·버전·본문 검증은 그대로 적용한다.

일일 수집에서 GitHub Release 게시 시각이 조회 시작 전이고 공식 노트가 없는 버전은
과거 미해결 목록으로 남긴다. 이 목록만으로 일일 완료를 차단하지 않는다.
이 구분은 재조사 우선순위이며, App Store 배포일이나 변경 0건을 확정하는 근거가 아니다.
매 새 실행에서 전체 배포 목록과 공식 노트, 필요한 App Store 이력을 다시 대조한다.
과거 버전의 공식 게시·수정 시각이 이번 기간에 해당하면 해당 항목을 수집한다.
이번 기간의 배포에 변경 안내가 없으면 계속 미완료로 둔다.
주간 전체 대조와 수동 수집은 과거 미해결 목록의 차단을 유지한다.
과거 미해결 목록과 실패 이유는 비공개 작업 파일에 보존한다.

## 나중에 확보한 근거와 설정 호환성

보완 근거는 새 실행 ID로 수집한다. 관측 시각과 공식 게시·수정 시각을 구분한다.
마감 후에 게시·수정된 내용은 다음 수집에서 처리하며 과거 마감의 근거로 소급하지 않는다.
과거 완료 결과의 건수·인용·리비전은 유지한다. 미확인 항목을 임의로 0건 처리하지 않는다.

같은 마감의 미완료 브라우저에 근거를 추가할 때는 기존 scope와 완료 브라우저를 유지한다.
설정의 `scope_note` 또는 JSON 공백만 바뀌었다면 Git 이력의 원본 설정을 해시로 확인하고
나머지 필드가 같은 경우에만 보완 저장을 허용한다. 기존 registry 해시는 교체하지 않는다.
URL, 활성 출처, parser, 수집 구간, 한도 등 다른 필드가 바뀌면 새 마감으로 수집한다.
출처 설정이 바뀐 기존 실행을 재개하거나 원문 캐시를 덮어쓰지 않는다.
