# Daily selected report contract

The renderer in [pipeline/reporting](../pipeline/reporting/README.md) creates this
format from public stored snapshots. This file is a format guide, not a report.

1. KST date, inclusive cutoff, report revision and comparison window.
2. Public collection/evaluation completeness. Show limitations when incomplete.
3. New or changed selected features and experiments. Link the full current lists.
4. For each subject: selection action, timing class, public fact summary, separate
   announcement/effective/observation/selection dates, PM reasons, comparison task,
   conditional benchmark and fixed evidence references.
5. Current-card subject replacements, with both actual judgments. Do not label a
   catalog replacement as a new PM judgment of the earlier subject.
6. Fixed selected snapshots and immutable report metadata.

Keep one section per subject in the window. Link earlier same-day judgment changes.
Do not call backfill a launch. Do not convert a failure into “no changes”. Preserve
manual reports and every generated revision. Keep private operation details out.
